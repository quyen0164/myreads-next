GIT CHEAT SHEET — BẢN RÀ SOÁT 2026

Tra cứu lệnh Git, ý nghĩa, flag và workflow thường dùng. Tài liệu này ưu tiên tính chính xác và an toàn hơn việc liệt kê mọi option có thể có.

Trước khi chạy lệnh: dùng git status để xem trạng thái hiện tại. Các lệnh như git reset --hard, git clean -fd, git rm -rf và git push --force có thể làm mất dữ liệu hoặc ghi đè lịch sử. Đọc kỹ phần cảnh báo trước khi sử dụng.

1. Khởi tạo & Cấu hình

1.1. Cài đặt Git

git --version

Nghĩa: Phiên bản — Kiểm tra Git đã cài chưa
git --version
# Kết quả: git version 2.42.0

1.2. Cấu hình tác giả commit

Đây là tên và email được ghi vào metadata của commit; chúng không tự đăng nhập GitHub cho a. Dùng --global để áp dụng cho các repository của user hiện tại trên máy này.

git config --global user.name

Nghĩa: đặt tên tác giả commit
git config --global user.name "Nguyen Van A"

git config --get user.name # Đọc lại giá trị đang áp dụng

git config --global user.email

Nghĩa: đặt email tác giả commit
git config --global user.email "a@example.com"
git config --get user.email

Dùng email mà a muốn gắn với commit. Nếu chỉ muốn áp dụng trong một repo, bỏ --global và chạy lệnh từ thư mục repo đó.

1.3. git init — Tạo project mới từ đầu

PHẦN QUAN TRỌNG NHẤT KHI BẮT ĐẦU
Khi có thư mục code chưa được quản lý bởi Git, chạy git init tại thư mục đó. Nếu project đã clone từ GitHub hoặc đã có thư mục .git, thường không cần chạy lại. Chạy nhầm git init trong một thư mục con có thể tạo repository lồng nhau.

git init

Nghĩa: Khởi tạo — Tạo Git repo mới trong folder hiện tại
git init

1.4. git clone — Lấy project có sẵn

git clone

Nghĩa: Sao chép — Tải repo từ GitHub về máy
git clone https://github.com/user/repo.git

1.5. git checkout --orphan — Tạo nhánh có lịch sử độc lập

Đây không phải cách thông thường để làm lại một project.
--orphan tạo nhánh mới không có commit cha; commit đầu tiên trên nhánh đó sẽ mở đầu một lịch sử Git độc lập. Tuy nhiên, ngay sau lệnh, index và working tree ban đầu vẫn được điền theo commit hiện tại. Chỉ khi muốn tạo cây file hoàn toàn khác mới cần dọn chúng. Cách này thường dùng cho mục đích đặc biệt, chẳng hạn xuất bản một cây file mà không mang theo lịch sử cũ.

git switch --orphan <tên_nhánh> (hoặc git checkout --orphan)

Nghĩa: tạo nhánh mới không kế thừa lịch sử commit
# Xem trạng thái và sao lưu/commit các thay đổi cần giữ trước.
git status

# Tạo nhánh có lịch sử độc lập; file hiện tại có thể vẫn xuất hiện.
git switch --orphan history-moi

# CHỈ dùng nếu muốn dọn các file đang được Git theo dõi khỏi index và working tree.
# Lệnh này có tính phá hủy; kiểm tra kỹ trước khi chạy.
git rm -rf .

# Thêm các file mới cần lưu trên lịch sử độc lập.
git add .
git status
git commit -m "Start independent history"

Giải thích flag:

Cú phápNghĩa
--orphan <branch>Tạo nhánh chưa có commit cha; commit đầu tiên tạo lịch sử độc lập.
git rm -rf .-r: xử lý thư mục đệ quy; -f: ép xóa các đường dẫn được Git quản lý. Lệnh không phải công cụ để xóa mọi file untracked/ignored trong thư mục.

Không chạy ví dụ này trong project đang làm nếu a chưa sao lưu hoặc chưa hiểu chính xác file nào sẽ bị xóa. Nếu mục tiêu chỉ là bắt đầu tính năng mới, hãy dùng git switch -c feature/ten-tinh-nang.

2. 4 tầng của Git

Working Directory (File a đang sửa; có thể có file mới chưa theo dõi)
▼ git add <file> / git add -A
Staging Area / Index (Snapshot những thay đổi chuẩn bị commit)
▼ git commit
Local Repository (Lịch sử commit trên máy)
▼ git push
Remote Repository (Ví dụ GitHub/GitLab; nơi chia sẻ lịch sử)

3. Kiểm tra trạng thái

git status

Nghĩa: Trạng thái — Xem file đã sửa, file mới, file đã stage
git status
 git status -sb # Dạng ngắn: branch + trạng thái file

git diff

Nghĩa: xem khác biệt giữa các trạng thái file
git diff                 # Thay đổi chưa stage so với index
git diff --staged        # Thay đổi đã stage so với commit hiện tại
git diff HEAD            # Tổng thay đổi tracked so với HEAD
git diff -- file.txt     # Chỉ xem một file

4. Add & Commit

git add

Nghĩa: Thêm — Đưa file vào Staging Area
git add file.txt       # Stage một file
git add .              # Stage thay đổi dưới thư mục hiện tại
git add -A             # Stage mọi thay đổi trong working tree (thêm/sửa/xóa)
git add -p             # Chọn từng phần thay đổi để stage

Trước khi commit, kiểm tra nội dung đã stage bằng git diff --staged. git add không lưu lịch sử; nó chỉ chuẩn bị nội dung cho commit.

git commit

Nghĩa: Ghi lại — Lưu thay đổi thành 1 commit
git commit -m "Nội dung commit" # Commit với message
git commit --amend # Sửa commit cuối; có thể thay đổi hash

Nếu bỏ -m, Git mở editor được cấu hình trên máy (không nhất thiết là Vim). Chỉ dùng --amend với commit đã chia sẻ khi a hiểu tác động của việc viết lại lịch sử.

5. Xem lịch sử

git log

Nghĩa: Nhật ký — Xem lịch sử commit
git log --oneline --graph --all

6. Branch

git branch & git switch

Nghĩa: Nhánh — Quản lý nhánh
git branch                    # Liệt kê branch local
git branch -a                 # Local + remote-tracking branches
git branch -vv                # Xem upstream và trạng thái ahead/behind
git switch -c feature/ten-tinh-nang  # Tạo branch và chuyển sang đó
git switch main               # Chuyển sang branch main
git branch -d feature/ten     # Xóa branch local đã merge
git push origin --delete feature/ten # Xóa branch trên remote

git branch -d thường từ chối xóa branch chưa merge. -D ép xóa; chỉ dùng khi đã chắc chắn không cần các commit riêng trên branch đó.

7. Merge & Conflict

git merge

Nghĩa: Hợp nhất — Gộp branch vào branch hiện tại
git switch main
 git pull --ff-only origin main # Cập nhật main nếu có thể fast-forward
 git merge feature/ten-tinh-nang # Gộp feature vào branch hiện tại (main)
 git status

Nếu merge conflict, Git sẽ báo những file cần xử lý. Không chạy tiếp các lệnh khác một cách đoán mò; xem mục Xử lý merge conflict.

Quy trình xử lý conflict chi tiết nằm ở mục 27.

8. Push, Pull, Fetch

git push / pull / fetch

Nghĩa: Đẩy / Kéo / Lấy
git fetch origin                 # Tải thông tin/commit mới; chưa tích hợp vào branch hiện tại
git pull --ff-only               # Fetch rồi tích hợp nếu chỉ cần fast-forward
git push origin main             # Đẩy branch local main lên branch main trên origin
git push -u origin ten-branch    # Push lần đầu và đặt upstream

Phân biệt: fetch cập nhật dữ liệu remote-tracking; pull là fetch rồi tích hợp vào branch hiện tại (thường merge hoặc rebase tùy cấu hình/cờ); push gửi các ref/commit local lên remote. Trước khi pull, kiểm tra và commit/stash thay đổi local nếu cần.

9. Upstream & Push branch mới

-u (--set-upstream)

Nghĩa: đặt upstream/tracking branch cho branch local
git push -u origin taomoi
# Sau này, khi đang ở taomoi, thường chỉ cần:
git push
git pull

Upstream là branch remote mà branch local theo dõi (ví dụ local taomoi theo dõi origin/taomoi). Nó giúp Git biết mặc định sẽ pull/push với nhánh nào.

10. Hoàn tác

git restore / reset / revert

Nghĩa: Khôi phục / Đặt lại / Đảo ngược
git restore file.txt              # Bỏ thay đổi CHƯA stage của file; có thể mất phần sửa đó
git restore --staged file.txt     # Bỏ stage, vẫn giữ sửa đổi trong working tree
git reset --soft HEAD~1           # Bỏ commit cuối khỏi branch; thay đổi vẫn staged
git reset --mixed HEAD~1          # Mặc định: bỏ commit khỏi branch; thay đổi còn ở working tree, unstaged
git reset --hard HEAD~1           # Di chuyển HEAD/branch và làm sạch index + tracked working tree; nguy hiểm
git revert <hash>                 # Tạo commit mới đảo ngược thay đổi của commit đã chọn
Cảnh báo: reset --hard có thể xóa thay đổi tracked chưa commit. restore cũng có thể loại bỏ phần sửa của file. Hãy chạy git status và sao lưu/stash trước khi hoàn tác. Với commit đã push/chia sẻ, thường ưu tiên git revert để không viết lại lịch sử chung.

11. Stash

git stash

Nghĩa: Cất tạm — Cất thay đổi chưa commit đi chỗ khác
git stash push -m "tam-cat-cong-viec" # Cất thay đổi tracked, kèm ghi chú
git stash push -u -m "them-file-moi"  # Thêm cả file untracked
git stash list                         # Xem các stash
git stash show -p stash@{0}            # Xem diff của stash mới nhất
git stash apply stash@{0}              # Áp dụng lại nhưng giữ stash
git stash pop                          # Áp dụng rồi xóa stash nếu áp dụng thành công

Mặc định, git stash không cất file untracked. Dùng -u nếu muốn cất cả file mới chưa được Git theo dõi. Nếu áp dụng stash bị conflict, stash thường vẫn được giữ lại để xử lý.

12. Remote

git remote

Nghĩa: Từ xa — Quản lý kết nối GitHub
git remote -v                         # Xem URL fetch/push
git remote add origin <URL>           # Thêm remote tên origin
git remote set-url origin <URL-moi>   # Đổi URL remote
git fetch origin                      # Cập nhật dữ liệu từ remote

origin chỉ là tên thường dùng cho remote mặc định; có thể đặt tên khác. Remote là địa chỉ kho Git từ xa, không nhất thiết phải là GitHub.

13. .gitignore

File .gitignore quy định những file chưa được theo dõi mà Git nên bỏ qua, ví dụ thư mục dependency, file build hoặc secret local.

node_modules/
dist/
.env
*.log
.next/
Lưu ý quan trọng: nếu file đã được track/commit từ trước, thêm nó vào .gitignore không tự bỏ file khỏi Git. Để ngừng track nhưng vẫn giữ file trên máy, dùng git rm --cached <file> hoặc với thư mục dùng git rm -r --cached <folder>, sau đó commit thay đổi. Đừng commit API key, mật khẩu hoặc token.

14. Tag

git tag

Nghĩa: Thẻ — Đánh dấu phiên bản (VD: v1.0.0)
git tag -a v1.0.0 -m "Release 1.0.0"  # Tạo annotated tag
git tag                                  # Liệt kê tag local
git show v1.0.0                          # Xem thông tin tag
git push origin v1.0.0                   # Đẩy một tag lên remote
git push origin --tags                   # Đẩy tất cả tag local

15. Workflow hàng ngày

Ví dụ khi làm việc trên branch main. Trong team, nên phát triển trên feature branch và tạo Pull Request theo quy trình của nhóm.
git status                         # Kiểm tra trước khi làm
git switch main
git pull --ff-only origin main      # Lấy cập nhật an toàn nếu có thể fast-forward
git switch -c feature/ten-tinh-nang
# Sửa code...
git status
git diff                            # Kiểm tra thay đổi chưa stage
git add -A
git diff --staged                   # Kiểm tra những gì sắp commit
git commit -m "Add feature"
git push -u origin feature/ten-tinh-nang

Nếu git pull --ff-only bị từ chối vì lịch sử đã phân nhánh, đừng vội dùng reset/force; xem git status, git log và quy trình merge/rebase của project.

16. Lệnh nâng cao

git rebase / cherry-pick / reflog

git fetch origin
git rebase origin/main          # Đưa commit của branch hiện tại lên trên origin/main
git cherry-pick <hash>           # Áp dụng một commit cụ thể lên branch hiện tại
git reflog                      # Xem lịch sử di chuyển HEAD/ref trên máy
git push --force-with-lease     # Chỉ cân nhắc sau khi đã rewrite history và hiểu tác động
Rebase và force push: không rebase/force-push branch dùng chung của nhóm nếu chưa thống nhất. --force-with-lease có kiểm tra remote tip tốt hơn --force, nhưng vẫn có thể thay đổi lịch sử remote.

18. Flag thường gặp — Ý nghĩa phụ thuộc vào lệnh

Không có bảng dịch flag nào đúng cho mọi lệnh Git. Cùng một chữ viết tắt có thể có ý nghĩa khác nhau ở lệnh khác nhau. Luôn đọc flag cùng với tên lệnh.
FlagVí dụÝ nghĩa trong ngữ cảnh đó
-mgit commit -m "msg"--message: cung cấp commit message. Nhưng trong git branch -m, -m là đổi tên branch.
-agit branch -aỞ lệnh branch: hiển thị branch local và remote-tracking. Với git add -A, chữ dùng là -A, nghĩa là stage mọi thay đổi.
-bgit checkout -b featureTạo branch rồi chuyển sang branch đó. Với lệnh mới, thường dùng git switch -c feature.
-ugit push -u origin featureỞ lệnh push: --set-upstream, đặt branch remote theo dõi. Trong lệnh khác, -u có thể mang nghĩa khác.
--stagedgit diff --stagedXem thay đổi đang nằm trong Staging Area.
--onelinegit log --onelineRút gọn mỗi commit thành một dòng.
--graphgit log --graphHiển thị nhánh lịch sử bằng đồ họa ký tự.
--allgit log --allHiển thị commit reachable từ mọi ref mà log xét, không chỉ HEAD hiện tại.
--force-with-leasegit push --force-with-leaseForce-update có điều kiện dựa trên remote-tracking expectation; vẫn có rủi ro viết lại lịch sử.

26. 5 quy tắc vàng

  1. git status trước mọi thao tác quan trọng.
  2. git diff và git diff --staged để kiểm tra đúng phần thay đổi.
  3. Commit nhỏ, message nói rõ mục đích thay đổi.
  4. Fetch rồi tích hợp theo workflow của nhóm trước khi push; không pull mù quáng khi working tree đang có thay đổi.
  5. Không dùng reset --hard, clean -fd hay force push nếu chưa hiểu tác động.

27. Quy trình xử lý merge conflict

Conflict xảy ra khi Git không thể tự kết hợp các thay đổi, ví dụ hai nhánh sửa cùng vùng của một file. Conflict không có nghĩa Git đã làm hỏng project; nó cần a quyết định nội dung cuối cùng.

git status                       # Xem file đang conflict
# Mở file; xử lý các marker <<<<<<<, =======, >>>>>>> trong editor
git diff                         # Xem phần thay đổi
git add <file-da-giai-quyet>     # Đánh dấu file conflict đã được giải quyết
git status
git merge --continue             # Tiếp tục merge nếu Git yêu cầu
# Hoặc: git merge --abort để hủy merge chưa hoàn tất
Nếu đang rebase thay vì merge, dùng git rebase --continue hoặc git rebase --abort. Hãy biết mình đang trong quy trình nào trước khi chạy lệnh tiếp theo.

28. Lệnh an toàn và lệnh nguy hiểm

LệnhTác độngCách dùng an toàn hơn
git reset --hardĐặt lại HEAD/index/working tree; có thể loại bỏ thay đổi tracked chưa commit.Chạy git status, tạo backup/commit hoặc stash trước.
git clean -fdXóa file/thư mục untracked; không có Undo của Git cho file đó.Chạy git clean -nd để xem trước danh sách sẽ xóa.
git rm -rf .Gỡ các đường dẫn được Git theo dõi khỏi index và working tree.Chỉ dùng trong workflow có chủ đích như tạo nhánh orphan mới, sau khi hiểu tác động.
git push --forceCó thể ghi đè lịch sử branch trên remote, ảnh hưởng người khác.Tránh trên branch dùng chung; nếu bắt buộc viết lại lịch sử, hiểu rõ quy trình và cân nhắc --force-with-lease.
git restore <file>Bỏ thay đổi chưa stage của file.Xem git diff -- <file> và sao lưu phần cần giữ trước.
