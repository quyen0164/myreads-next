Lộ trình 1 — SQLite Driver + SQL trực tiếp (học trước Prisma)

Ở chương này, a sẽ xây dựng phần database MyReads bằng SQL trực tiếp + driver better-sqlite3, chưa dùng ORM. Sau khi hiểu bảng, khóa, quan hệ và CRUD, a sẽ học Prisma ở các chương phía sau và so sánh cách ORM biểu diễn cùng những ý tưởng đó.

Thứ tự học đề xuất: (1) hiểu quan hệ dữ liệu; (2) tạo database và bảng bằng SQL; (3) kết nối bằng driver; (4) viết CRUD; (5) gọi CRUD từ Next.js Server Actions; (6) sau khi thuần thục mới chuyển sang Prisma. Chương này dành cho Next.js App Router, không phải project React + Vite thuần.
Không chạy cả hai track lên cùng một file DB. Ví dụ driver sử dụng data/myreads-driver.db; phần Prisma dùng database theo DATABASE_URL. Tách riêng giúp a thử nghiệm mà không làm lẫn dữ liệu hoặc cấu trúc.

2.1. Lược đồ quan hệ cần xây dựng

users (1) ──── (N) reviews (N) ──── (1) books │ │ └── (1) ──── (N) user_books (N) ─────────┘ │ books (1) ──── (N) book_authors (N) ──── (1) authors books (1) ──── (N) book_categories (N) ── (1) categories

Trong sơ đồ, bảng nối ở giữa biến quan hệ N–N thành hai quan hệ 1–N. Các bảng nối dùng khóa chính ghép để ngăn cùng một cặp được liên kết lặp lại.

2.2. File lib/db.ts: kết nối và tạo các bảng

File này làm ba việc: (1) tạo thư mục lưu database nếu chưa có; (2) mở file SQLite; (3) bật kiểm tra foreign key và tạo bảng bằng SQL. CREATE TABLE IF NOT EXISTS chỉ tạo bảng khi chưa tồn tại, nó không tự thay đổi bảng cũ nếu a sửa định nghĩa.

lib/db.ts — database driver và schema SQL · TYPESCRIPT + SQL
import "server-only";
import Database from "better-sqlite3";
import { mkdirSync } from "node:fs";
import path from "node:path";

// process.cwd() trả về thư mục mà lệnh npm được chạy từ đó.
// Ví dụ: F:\kadane\myreads-next
const dataDir = path.join(process.cwd(), "data");
const dbPath = path.join(dataDir, "myreads-driver.db");

// Tạo thư mục data nếu chưa tồn tại; recursive tạo cả thư mục cha còn thiếu.
mkdirSync(dataDir, { recursive: true });

function openDatabase() {
  // Mở database; nếu file chưa tồn tại, SQLite sẽ tạo file mới.
  const connection = new Database(dbPath);

  // SQLite có thể cần bật foreign_keys riêng cho từng connection.
  // Khi bật, nó sẽ kiểm tra các giá trị khóa ngoại và thực hiện ON DELETE CASCADE.
  connection.pragma("foreign_keys = ON");

  // WAL là journal mode, giúp đọc/ghi đồng thời tốt hơn trong nhiều trường hợp.
  connection.pragma("journal_mode = WAL");

  // exec() chạy các câu SQL không trả về một danh sách hàng như SELECT.
  // Mỗi CREATE TABLE định nghĩa một bảng và các ràng buộc dữ liệu.
  connection.exec(`
    CREATE TABLE IF NOT EXISTS users (
      id TEXT PRIMARY KEY NOT NULL,
      name TEXT NOT NULL,
      email TEXT NOT NULL UNIQUE,
      created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
    );

    CREATE TABLE IF NOT EXISTS books (
      id TEXT PRIMARY KEY NOT NULL,
      title TEXT NOT NULL,
      isbn TEXT UNIQUE,
      published_year INTEGER CHECK (
        published_year IS NULL OR published_year BETWEEN 1000 AND 2100
      ),
      created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP
    );

    CREATE TABLE IF NOT EXISTS authors (
      id TEXT PRIMARY KEY NOT NULL,
      name TEXT NOT NULL COLLATE NOCASE UNIQUE,
      bio TEXT
    );

    CREATE TABLE IF NOT EXISTS categories (
      id TEXT PRIMARY KEY NOT NULL,
      name TEXT NOT NULL COLLATE NOCASE UNIQUE
    );

    -- Bảng nối: một sách có nhiều tác giả; một tác giả có nhiều sách.
    CREATE TABLE IF NOT EXISTS book_authors (
      book_id TEXT NOT NULL,
      author_id TEXT NOT NULL,
      author_order INTEGER NOT NULL DEFAULT 1,
      PRIMARY KEY (book_id, author_id),
      FOREIGN KEY (book_id) REFERENCES books(id) ON DELETE CASCADE,
      FOREIGN KEY (author_id) REFERENCES authors(id) ON DELETE CASCADE
    );

    -- Bảng nối: một sách có nhiều thể loại và ngược lại.
    CREATE TABLE IF NOT EXISTS book_categories (
      book_id TEXT NOT NULL,
      category_id TEXT NOT NULL,
      PRIMARY KEY (book_id, category_id),
      FOREIGN KEY (book_id) REFERENCES books(id) ON DELETE CASCADE,
      FOREIGN KEY (category_id) REFERENCES categories(id) ON DELETE CASCADE
    );

    -- Kệ là quan hệ giữa người dùng và sách, không phải thuộc tính của sách toàn cục.
    -- Composite primary key đảm bảo mỗi user chỉ có một trạng thái cho mỗi book.
    CREATE TABLE IF NOT EXISTS user_books (
      user_id TEXT NOT NULL,
      book_id TEXT NOT NULL,
      shelf TEXT NOT NULL DEFAULT 'want_to_read'
        CHECK (shelf IN ('want_to_read', 'reading', 'read')),
      notes TEXT,
      updated_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
      PRIMARY KEY (user_id, book_id),
      FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
      FOREIGN KEY (book_id) REFERENCES books(id) ON DELETE CASCADE
    );

    -- Một user chỉ có tối đa một review cho cùng một book.
    CREATE TABLE IF NOT EXISTS reviews (
      id TEXT PRIMARY KEY NOT NULL,
      user_id TEXT NOT NULL,
      book_id TEXT NOT NULL,
      rating INTEGER NOT NULL CHECK (rating BETWEEN 1 AND 5),
      content TEXT NOT NULL DEFAULT '',
      created_at TEXT NOT NULL DEFAULT CURRENT_TIMESTAMP,
      UNIQUE (user_id, book_id),
      FOREIGN KEY (user_id) REFERENCES users(id) ON DELETE CASCADE,
      FOREIGN KEY (book_id) REFERENCES books(id) ON DELETE CASCADE
    );
  `);

  return connection;
}

// Lấy kiểu của kết nối do openDatabase() trả về.
type DatabaseConnection = ReturnType<typeof openDatabase>;

// Giữ một connection dùng chung qua hot reload ở môi trường phát triển.
const globalForDb = globalThis as unknown as {
  myReadsDb?: DatabaseConnection;
};

export const db = globalForDb.myReadsDb ?? openDatabase();

if (process.env.NODE_ENV !== "production") {
  globalForDb.myReadsDb = db;
}

3. Tạo dữ liệu mẫu (seed) để thử relationship

Ta cần các bản ghi ở bảng cha trước khi thêm bảng nối. Ví dụ phải có user, book, author và category trước, rồi mới tạo dòng trong book_authors, book_categories, user_books và reviews.

3.1. Quan sát dữ liệu quan hệ bằng SQL JOIN

JOIN ghép dữ liệu từ nhiều bảng dựa trên một điều kiện. Truy vấn sau lấy sách, tác giả, thể loại và kệ của một người. Các bảng nối được truy vấn trong các truy vấn con để tránh nhân đôi sách khi một sách có nhiều tác giả và nhiều thể loại.

Ví dụ SQL JOIN và truy vấn con · SQL
SELECT
  b.id,
  b.title,
  b.published_year,
  COALESCE((
    SELECT group_concat(a.name, ', ')
    FROM book_authors ba
    JOIN authors a ON a.id = ba.author_id
    WHERE ba.book_id = b.id
  ), '') AS authors,
  COALESCE((
    SELECT group_concat(c.name, ', ')
    FROM book_categories bc
    JOIN categories c ON c.id = bc.category_id
    WHERE bc.book_id = b.id
  ), '') AS categories,
  ub.shelf,
  (SELECT ROUND(AVG(r.rating), 1)
   FROM reviews r WHERE r.book_id = b.id) AS avg_rating
FROM books b
LEFT JOIN user_books ub
  ON ub.book_id = b.id AND ub.user_id = ?
ORDER BY b.title COLLATE NOCASE;

LEFT JOIN giữ lại cả những cuốn chưa có trạng thái kệ cho user đó. COALESCE thay giá trị NULL bằng chuỗi rỗng. Truy vấn con tính danh sách tác giả/thể loại và điểm đánh giá trung bình cho từng cuốn.

3.2. Cài các kiểu TypeScript và hàm CRUD

Không dùng ORM nghĩa là a tự viết SQL. Ta tách SQL vào lib/books.ts, tránh đặt câu truy vấn rải rác trong giao diện. Các hàm dưới đây dùng prepared statements với placeholder ?, không ghép input người dùng trực tiếp vào câu SQL.

lib/books.ts — truy vấn có quan hệ và CRUD · TYPESCRIPT + SQL
import "server-only";
import { randomUUID } from "node:crypto";
import { db } from "@/lib/db";

export type Shelf = "want_to_read" | "reading" | "read";

export type BookListItem = {
  id: string;
  title: string;
  isbn: string | null;
  published_year: number | null;
  authors: string;
  categories: string;
  shelf: Shelf | null;
  avg_rating: number | null;
  my_rating: number | null;
  my_review: string | null;
};

// READ: lấy danh sách sách cùng tác giả, thể loại và dữ liệu của một user.
export function listBooksForUser(userId: string): BookListItem[] {
  const rows = db.prepare(`
    SELECT b.id, b.title, b.isbn, b.published_year,
      COALESCE((SELECT group_concat(a.name, ', ')
        FROM book_authors ba JOIN authors a ON a.id = ba.author_id
        WHERE ba.book_id = b.id), '') AS authors,
      COALESCE((SELECT group_concat(c.name, ', ')
        FROM book_categories bc JOIN categories c ON c.id = bc.category_id
        WHERE bc.book_id = b.id), '') AS categories,
      ub.shelf,
      (SELECT ROUND(AVG(r.rating), 1) FROM reviews r WHERE r.book_id = b.id) AS avg_rating,
      (SELECT r.rating FROM reviews r WHERE r.book_id = b.id AND r.user_id = ?) AS my_rating,
      (SELECT r.content FROM reviews r WHERE r.book_id = b.id AND r.user_id = ?) AS my_review
    FROM books b
    LEFT JOIN user_books ub ON ub.book_id = b.id AND ub.user_id = ?
    ORDER BY b.title COLLATE NOCASE
  `).all(userId, userId, userId);

  // Assertion chỉ hướng dẫn TypeScript; không tự validate dữ liệu runtime.
  return rows as BookListItem[];
}

// Hàm phụ: tìm hoặc tạo tác giả theo tên. Dùng trong transaction tạo sách.
function getOrCreateAuthor(name: string): string {
  const cleanName = name.trim();
  if (!cleanName) throw new Error("Tên tác giả không được để trống.");
  db.prepare(`INSERT OR IGNORE INTO authors (id, name) VALUES (?, ?)`)
    .run(randomUUID(), cleanName);
  const row = db.prepare(`SELECT id FROM authors WHERE name = ? COLLATE NOCASE`)
    .get(cleanName) as { id: string } | undefined;
  if (!row) throw new Error("Không thể tìm hoặc tạo tác giả.");
  return row.id;
}

// Hàm phụ: tìm hoặc tạo thể loại theo tên.
function getOrCreateCategory(name: string): string {
  const cleanName = name.trim();
  if (!cleanName) throw new Error("Tên thể loại không được để trống.");
  db.prepare(`INSERT OR IGNORE INTO categories (id, name) VALUES (?, ?)`)
    .run(randomUUID(), cleanName);
  const row = db.prepare(`SELECT id FROM categories WHERE name = ? COLLATE NOCASE`)
    .get(cleanName) as { id: string } | undefined;
  if (!row) throw new Error("Không thể tìm hoặc tạo thể loại.");
  return row.id;
}

export type CreateBookInput = {
  title: string;
  isbn: string | null;
  publishedYear: number | null;
  authorNames: string[];
  categoryNames: string[];
};

// CREATE: thêm sách và liên kết tác giả/thể loại trong một transaction.
export function createBook(input: CreateBookInput): string {
  const title = input.title.trim();
  if (!title) throw new Error("Tên sách không được để trống.");

  const transaction = db.transaction(() => {
    const id = randomUUID();
    db.prepare(`INSERT INTO books (id, title, isbn, published_year)
                VALUES (?, ?, ?, ?)`).run(
      id, title, input.isbn?.trim() || null, input.publishedYear
    );

    // Tạo/fetch tác giả rồi thêm quan hệ qua bảng nối book_authors.
    input.authorNames.map((name) => name.trim()).filter(Boolean)
      .forEach((name, index) => {
        const authorId = getOrCreateAuthor(name);
        db.prepare(`INSERT OR IGNORE INTO book_authors (book_id, author_id, author_order)
                    VALUES (?, ?, ?)`).run(id, authorId, index + 1);
      });

    // Tạo/fetch thể loại rồi thêm quan hệ qua bảng nối book_categories.
    input.categoryNames.map((name) => name.trim()).filter(Boolean)
      .forEach((name) => {
        const categoryId = getOrCreateCategory(name);
        db.prepare(`INSERT OR IGNORE INTO book_categories (book_id, category_id)
                    VALUES (?, ?)`).run(id, categoryId);
      });

    return id;
  });

  // Transaction: nếu một thao tác trong khối lỗi, nhóm thay đổi được rollback.
  return transaction();
}

// UPDATE: tạo hoặc cập nhật kệ sách của một người dùng.
export function setUserShelf(userId: string, bookId: string, shelf: Shelf): void {
  const allowed: Shelf[] = ["want_to_read", "reading", "read"];
  if (!allowed.includes(shelf)) throw new Error("Kệ sách không hợp lệ.");

  db.prepare(`
    INSERT INTO user_books (user_id, book_id, shelf, updated_at)
    VALUES (?, ?, ?, CURRENT_TIMESTAMP)
    ON CONFLICT(user_id, book_id) DO UPDATE SET
      shelf = excluded.shelf,
      updated_at = CURRENT_TIMESTAMP
  `).run(userId, bookId, shelf);
}

// CREATE/UPDATE review: UNIQUE(user_id, book_id) cho phép mỗi user một review/book.
export function saveReview(userId: string, bookId: string, rating: number, content: string): void {
  if (!Number.isInteger(rating) || rating < 1 || rating > 5) {
    throw new Error("Điểm đánh giá phải từ 1 đến 5.");
  }

  db.prepare(`
    INSERT INTO reviews (id, user_id, book_id, rating, content)
    VALUES (?, ?, ?, ?, ?)
    ON CONFLICT(user_id, book_id) DO UPDATE SET
      rating = excluded.rating,
      content = excluded.content,
      created_at = CURRENT_TIMESTAMP
  `).run(randomUUID(), userId, bookId, rating, content.trim());
}

// DELETE: foreign keys + ON DELETE CASCADE sẽ xóa các liên kết và review của sách.
export function deleteBook(bookId: string): void {
  const result = db.prepare(`DELETE FROM books WHERE id = ?`).run(bookId);
  if (result.changes === 0) throw new Error("Không tìm thấy sách để xóa.");
}

4. Server Actions cho CREATE, UPDATE, REVIEW và DELETE

Server Action là hàm phía server được form gọi. File nằm trong app/actions/books.ts. Mỗi thao tác nhận FormData, kiểm tra input, gọi hàm ở lib/books.ts, sau đó revalidatePath("/") yêu cầu Next.js làm mới dữ liệu cho trang chủ.

app/actions/books.ts — Server Actions · TYPESCRIPT
"use server";

import { revalidatePath } from "next/cache";
import { createBook, deleteBook, saveReview, setUserShelf, type Shelf } from "@/lib/books";

// Đây là user mẫu trong seed-driver.ts. Ứng dụng thật phải lấy user ID từ session đăng nhập.
const DEMO_USER_ID = "user-demo";

function getText(formData: FormData, key: string): string {
  const value = formData.get(key);
  return typeof value === "string" ? value.trim() : "";
}

function splitNames(value: string): string[] {
  // Cho phép nhập nhiều tên cách nhau bằng dấu phẩy.
  return value.split(",").map((name) => name.trim()).filter(Boolean);
}

export async function createBookAction(formData: FormData) {
  const title = getText(formData, "title");
  const isbn = getText(formData, "isbn") || null;
  const yearText = getText(formData, "publishedYear");
  const publishedYear = yearText ? Number(yearText) : null;

  if (yearText && (!Number.isInteger(publishedYear) || publishedYear! < 1000 || publishedYear! > 2100)) {
    throw new Error("Năm xuất bản phải là số nguyên hợp lệ.");
  }

  createBook({
    title,
    isbn,
    publishedYear,
    authorNames: splitNames(getText(formData, "authors")),
    categoryNames: splitNames(getText(formData, "categories")),
  });

  revalidatePath("/");
}

export async function updateShelfAction(formData: FormData) {
  const bookId = getText(formData, "bookId");
  const shelfValue = getText(formData, "shelf");
  const allowed: Shelf[] = ["want_to_read", "reading", "read"];
  if (!bookId || !allowed.includes(shelfValue as Shelf)) throw new Error("Dữ liệu kệ sách không hợp lệ.");

  setUserShelf(DEMO_USER_ID, bookId, shelfValue as Shelf);
  revalidatePath("/");
}

export async function saveReviewAction(formData: FormData) {
  const bookId = getText(formData, "bookId");
  const rating = Number(getText(formData, "rating"));
  const content = getText(formData, "content");
  if (!bookId) throw new Error("Thiếu ID sách.");

  saveReview(DEMO_USER_ID, bookId, rating, content);
  revalidatePath("/");
}

export async function deleteBookAction(formData: FormData) {
  const bookId = getText(formData, "bookId");
  if (!bookId) throw new Error("Thiếu ID sách.");

  deleteBook(bookId);
  revalidatePath("/");
}

// defineConfig xác nhận cấu trúc config theo kiểu TypeScript.

import { defineConfig, env } from "prisma/config";

export default defineConfig({
  // File chứa các model User, Book và loại database.
  schema: "prisma/schema.prisma",

  migrations: {
    // Nơi lưu các file migration (các bước thay đổi schema).

    // Khi chạy `npx prisma db seed`, CLI thực thi lệnh này.

schema.prisma

Schema là bản mô tả cấu trúc dữ liệu để Prisma biết các bảng, cột, khóa và quan hệ. Nó chưa tự tạo bảng trong file SQLite; bước migration ở mục tiếp theo mới cập nhật database.

prisma/schema.prisma · Prisma Schema

generator client {
  // Generator được khuyến nghị cho project mới dùng Prisma 7.
  provider = "prisma-client"

  // Đường dẫn tính tương đối từ thư mục prisma/ tới generated/prisma/.
  output = "../generated/prisma"
}

// Chọn loại database. URL được đặt trong prisma7.config.ts ở Prisma 7.
datasource db {
  provider = "sqlite"
}

// Model User tương ứng với bảng người dùng.
model User {
  // Primary Key: ID duy nhất cho mỗi user. uuid() tạo UUID dạng chuỗi.
  id String @id @default(uuid())

  // Không cho phép hai user có cùng email.
  email String @unique

  // Tên hiển thị của user.
  name String

  // Một user có thể có nhiều sách. Đây là field quan hệ của Prisma,
  // không phải cột books được lưu trong bảng User.
  books Book[]
}

// Model Book tương ứng với bảng sách.
model Book {
  id String @id @default(uuid())

  title String

  // Trạng thái kệ, mặc định là "none". Server sẽ kiểm tra giá trị hợp lệ.
  shelf String @default("none")

  // Cột thật lưu ID của User sở hữu sách (foreign key).
  userId String

  // Khai báo quan hệ Book thuộc về một User.
  // fields=[userId] là cột FK; references=[id] trỏ tới User.id.
  // onDelete=Cascade: xóa User thì các Book liên quan cũng bị xóa.
  user User @relation(fields: [userId], references: [id], onDelete: Cascade)
}

seed.ts: dữ liệu mẫu

Seed là script thêm dữ liệu mẫu để có thể thử giao diện ngay. Config đã khai báo seed: "tsx prisma/seed.ts", nên sau khi file này tồn tại, chạy npx prisma db seed.

prisma/seed.ts · TypeScript
// Nạp DATABASE_URL từ .env khi chạy file này bằng tsx.
import "dotenv/config";
import { PrismaClient } from "../generated/prisma/client";
import { PrismaBetterSqlite3 } from "@prisma/adapter-better-sqlite3";

// Lấy đúng URL đã cấu hình trong .env.
const databaseUrl = process.env.DATABASE_URL ?? "file:./dev.db";

// Adapter là cầu nối giữa Prisma Client và driver SQLite.
const adapter = new PrismaBetterSqlite3({ url: databaseUrl });

// Tạo client dùng để query database.
const prisma = new PrismaClient({ adapter });

async function main() {
  // upsert = tìm theo email; nếu có thì update, nếu chưa có thì create.
  // Vì email là @unique nên có thể dùng làm điều kiện where.
  const user = await prisma.user.upsert({
    where: { email: "admin@test.com" },
    update: { name: "Admin" },
    create: { name: "Admin", email: "admin@test.com" },
  });

  // Kiểm tra xem sách mẫu đã có chưa để chạy seed nhiều lần không tạo trùng.
  const existingBook = await prisma.book.findFirst({
    where: { userId: user.id, title: "Clean Code" },
  });

  if (!existingBook) {
    // user.id là ID vừa lấy/tạo ở bước trên; gán làm foreign key cho Book.
    await prisma.book.create({
      data: { title: "Clean Code", shelf: "read", userId: user.id },
    });
  }

  console.log("Seed xong. User:", user.email);
}

// Bắt lỗi để thấy lý do nếu seed thất bại, sau đó luôn đóng client.
main()
  .catch((error: unknown) => {
    console.error("Seed thất bại:", error);
    process.exitCode = 1;
  })
  .finally(async () => {
    await prisma.$disconnect();
  });

Các ý quan trọng:

  • new PrismaClient({ adapter }) tạo đối tượng Prisma dùng adapter đã cấu hình.
  • async cho phép dùng await trong hàm.
  • await đợi Promise hoàn tất trước khi chạy dòng tiếp theo trong hàm đó. Nó không khóa CPU của toàn bộ Node.js.
  • upsert giúp User mẫu không bị tạo lặp vì email là duy nhất.
  • findFirst kiểm tra cuốn sách mẫu đã có chưa; nếu chưa có mới thêm.
  • $disconnect() đóng kết nối khi script kết thúc. Đây hợp lý với script chạy xong rồi thoát, khác với app server lâu dài.

lib/prisma.ts: Prisma Client

Tại sao tách file này? Nhiều trang và Server Action cần dùng database. Nếu mỗi file tự tạo new PrismaClient(), code bị lặp và trong chế độ hot reload có thể tạo nhiều client. File này tạo một nơi dùng chung.
lib/prisma.ts · TypeScript
import { PrismaClient } from "../generated/prisma/client";
import { PrismaBetterSqlite3 } from "@prisma/adapter-better-sqlite3";

// Gắn thuộc tính prisma lên globalThis để giữ client qua các lần hot reload
// trong chế độ development. TypeScript cần biết global này có thuộc tính nào.
const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};

function createPrismaClient() {
  // Lấy URL database do Next.js nạp từ .env. Báo lỗi rõ ràng nếu thiếu.
  const databaseUrl = process.env.DATABASE_URL;
  if (!databaseUrl) {
    throw new Error("Thiếu DATABASE_URL trong file .env");
  }

  // Adapter chuyển truy vấn của Prisma sang driver better-sqlite3.
  const adapter = new PrismaBetterSqlite3({ url: databaseUrl });

  // Tạo một Prisma Client mới với adapter đó.
  return new PrismaClient({ adapter });
}

// Dùng client đã có nếu tồn tại; nếu chưa thì khởi tạo mới.
export const prisma = globalForPrisma.prisma ?? createPrismaClient();

// Chỉ cache global khi development để tránh tạo nhiều client do hot reload.
if (process.env.NODE_ENV !== "production") {
  globalForPrisma.prisma = prisma;
}

Đây là mẫu singleton cho môi trường development. Nó không có nghĩa toàn bộ người dùng trên Internet sẽ dùng chung một kết nối vật lý; mỗi process/instance triển khai vẫn có vòng đời riêng. Không gọi $disconnect() sau từng request trong ứng dụng web lâu dài vì điều đó khiến lần query tiếp theo phải tạo kết nối lại.

app/page.tsx: đọc và hiển thị

File này là trang chính trong Next.js App Router. Vì không có chỉ thị "use client", nó là Server Component mặc định. Do đó, nó có thể gọi database ở phía server và không cần gửi mã truy vấn database ra trình duyệt.

app/page.tsx · TSX / React
import { prisma } from "../lib/prisma";
import { updateShelf } from "../actions/books";

// Không có "use client", nên đây là Server Component.
// Server Component có thể là async và truy vấn database ngay trên server.
export default async function Home() {
  // Lấy tất cả sách và thông tin User sở hữu mỗi sách.
  const books = await prisma.book.findMany({
    include: { user: true },
    orderBy: { title: "asc" },
  });

  return (
    <main style={{ padding: 40 }}>
      <h1>Tủ sách MyReads</h1>

      {books.length === 0 && <p>Chưa có sách. Hãy chạy lệnh seed.</p>}

      <ul>
        {books.map((book) => (
          // key giúp React nhận diện mỗi phần tử khi danh sách thay đổi.
          <li key={book.id} style={{ marginBottom: 20 }}>
            <strong>{book.title}</strong> — {book.user.name}
            <p>Trạng thái hiện tại: {book.shelf}</p>

            {/* Server Action nhận book.id đã bind và FormData khi submit. */}
            <form action={updateShelf.bind(null, book.id)}>
              <select name="shelf" defaultValue={book.shelf}>
                <option value="read">Đã đọc</option>
                <option value="none">Chưa xếp kệ</option>
              </select>
              <button type="submit">Cập nhật</button>
            </form>
          </li>
        ))}
      </ul>
    </main>
  );
}
  • findMany: lấy nhiều bản ghi Book.
  • include: { user: true }: yêu cầu trả kèm user liên quan để dùng book.user.name. Cách Prisma thực hiện truy vấn SQL cụ thể có thể khác tùy cấu hình.
  • map: biến mỗi bản ghi thành một phần tử giao diện.
  • key={book.id}: giúp React xác định phần tử nào tương ứng với bản ghi nào khi danh sách cập nhật.
  • form action: gọi Server Action khi gửi form. Không dùng onChange trong Server Component như ví dụ cũ, vì event handler phía trình duyệt cần Client Component.

actions/books.ts: cập nhật dữ liệu

Server Action là hàm chạy trên server mà form có thể gọi. Chỉ thị "use server" ở đầu file đánh dấu các hàm export trong file là Server Actions.

actions/books.ts · TypeScript
"use server";

import { prisma } from "../lib/prisma";
import { revalidatePath } from "next/cache";

// Chỉ cho phép những trạng thái mà UI của ví dụ này hỗ trợ.
const allowedShelves = new Set(["read", "none"]);

// Khi bind bookId vào form, Next.js truyền FormData làm đối số tiếp theo.
export async function updateShelf(bookId: string, formData: FormData) {
  // FormData là dữ liệu form gửi lên; không mặc định rằng nó luôn hợp lệ.
  const shelf = formData.get("shelf");

  // Xác nhận dữ liệu có phải chuỗi và thuộc danh sách cho phép.
  if (typeof shelf !== "string" || !allowedShelves.has(shelf)) {
    throw new Error("Trạng thái kệ không hợp lệ");
  }

  // Cập nhật cột shelf cho bản ghi có ID khớp.
  await prisma.book.update({
    where: { id: bookId },
    data: { shelf },
  });

  // Yêu cầu Next.js làm mới dữ liệu của route / sau mutation.
  revalidatePath("/");
}

Vì sao cần kiểm tra shelf? Dữ liệu gửi từ form có thể bị sửa thủ công trong trình duyệt. Không nên tin dữ liệu client một cách mù quáng. Ví dụ này kiểm tra giá trị nằm trong read hoặc none trước khi update.

revalidatePath("/") yêu cầu Next.js làm mới dữ liệu/render cho route gốc sau mutation để người dùng thấy trạng thái cập nhật. Ví dụ này chưa có đăng nhập/phân quyền; không dùng trực tiếp làm ứng dụng thật nơi người dùng phải bị giới hạn quyền sửa sách.

1. Component, JSX và TypeScript props

Component là một hàm trả về giao diện. props là dữ liệu mà component cha truyền vào component con. Khai báo kiểu TypeScript giúp biết component cần nhận dữ liệu gì.

  return (

3. State, sự kiện và useState

state là dữ liệu thay đổi theo tương tác của người dùng. Khi state đổi, React render lại component với giá trị mới.

5. Khi nào dùng useEffect?

Đừng dùng useEffect cho mọi thao tác. Nó phù hợp để đồng bộ với hệ thống bên ngoài React, ví dụ event listener, timer hoặc một thư viện không thuộc React. Trong Next.js, việc lấy dữ liệu từ database ở Server Component thường không cần useEffect.
Ví dụ dọn dẹp event listener · TSX
"use client";

import { useEffect } from "react";

export default function OnlineExample() {
  useEffect(() => {
    function handleResize() {
      console.log("Kích thước cửa sổ đã thay đổi");
    }

    window.addEventListener("resize", handleResize);
    return () => window.removeEventListener("resize", handleResize);
  }, []);

  return <p>Mở DevTools và thay đổi kích thước cửa sổ.</p>;
}

Mảng phụ thuộc [] có nghĩa effect chạy sau lần mount đầu tiên; hàm return bên trong dùng để dọn dẹp listener khi component bị tháo hoặc trước khi effect được chạy lại.

5. Server Action và cập nhật dữ liệu

"use server";

import { revalidatePath } from "next/cache";
import { prisma } from "../lib/prisma";

export async function updateShelf(formData: FormData) {
  const bookId = formData.get("bookId");
  const shelf = formData.get("shelf");

  // Kiểm tra dữ liệu nhận từ form trước khi dùng.
  if (

    (shelf !== "read" && shelf !== "none")

    where: { id: bookId },
    data: { shelf },
  });

  // Yêu cầu Next.js làm mới dữ liệu của trang chủ.
  revalidatePath("/");
}

2. Schema cơ bản

prisma/schema.prisma — User và Book · PRISMA
generator client {
  provider = "prisma-client"
  output   = "../generated/prisma"
}

datasource db {
  provider = "sqlite"
}

model User {
  id    String @id @default(uuid())
  email String @unique
  name  String
  books Book[]
}

model Book {
  id     String @id @default(uuid())
  title  String
  shelf  String @default("none")
  userId String
  user   User   @relation(
    fields: [userId],
    references: [id],
    onDelete: Cascade
  )
}
  • model mô tả một nhóm bản ghi, thường ánh xạ tới bảng database.
  • @id đánh dấu khóa chính; @unique yêu cầu giá trị không bị trùng.
  • books Book[] là phía quan hệ nhiều sách của một User; đây không phải cột chứa cả mảng trong bảng User.
  • userId và @relation mô tả liên kết từ Book đến User.
  • onDelete: Cascade cho phép database xóa sách liên quan khi User bị xóa; chỉ dùng nếu đúng quy tắc nghiệp vụ.

3. CRUD — Create, Read, Update, Delete

Các truy vấn thường dùng · TS
import { prisma } from "../lib/prisma";

// READ: lấy tất cả sách, sắp xếp theo tiêu đề.
const books = await prisma.book.findMany({
  orderBy: { title: "asc" },
});

// READ: tìm một User theo trường unique.
const user = await prisma.user.findUnique({
  where: { email: "admin@test.com" },
});

// CREATE: tạo một bản ghi sách.
const newBook = await prisma.book.create({
  data: {
    title: "Clean Code",
    shelf: "read",
    userId: "ID_CUA_USER_DA_TON_TAI",
  },
});

// UPDATE: cập nhật một bản ghi theo khóa duy nhất.
await prisma.book.update({
  where: { id: newBook.id },
  data: { shelf: "none" },
});

// UPSERT: tìm theo email; nếu có thì update, chưa có thì create.
await prisma.user.upsert({
  where: { email: "admin@test.com" },
  update: { name: "Admin mới" },
  create: { email: "admin@test.com", name: "Admin" },
});

// DELETE: xóa một bản ghi theo ID.
// Kiểm tra quyền và xác nhận trước khi xóa dữ liệu thật.
await prisma.book.delete({
  where: { id: newBook.id },
});
Lưu ý về ví dụ CREATE: ID_CUA_USER_DA_TON_TAI chỉ là placeholder để minh họa. Thay bằng user.id thực tế đã có trong database; nếu ID không tồn tại, ràng buộc quan hệ sẽ khiến truy vấn thất bại.

5. Prisma Client và adapter trong Prisma 7

lib/prisma.ts — tái sử dụng client khi phát triển · TS
import { PrismaClient } from "../generated/prisma/client";
import { PrismaBetterSqlite3 } from "@prisma/adapter-better-sqlite3";

const globalForPrisma = globalThis as unknown as {
  prisma: PrismaClient | undefined;
};

function createPrismaClient() {
  const adapter = new PrismaBetterSqlite3({
    url: process.env.DATABASE_URL ?? "file:./dev.db",
  });
  return new PrismaClient({ adapter });
}

export const prisma = globalForPrisma.prisma ?? createPrismaClient();

if (process.env.NODE_ENV !== "production") {
  globalForPrisma.prisma = prisma;
}

PrismaClient là API TypeScript dùng để query; PrismaBetterSqlite3 là adapter kết nối tới driver SQLite. Biến globalForPrisma giúp tái sử dụng instance trong quá trình hot reload ở development.

Database URL phải thống nhất: dùng cùng URL trong cấu hình CLI và trong runtime. Nếu một bên trỏ tới file:./dev.db nhưng bên kia trỏ tới file khác, migration có thể chạy thành công nhưng trang vẫn hiện dữ liệu rỗng.
